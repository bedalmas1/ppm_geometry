# Phase 5 — Geometry Metric Implementation & Synthetic Validation

Produced per [`PLAN.md`](../PLAN.md) Phase 5 / spec §8, §9, §22 ("Implement a modular geometry-analysis package... construct synthetic latent trajectories to validate every metric... **do this before analyzing any real model**"). No real cached embedding from Phase 4 is read anywhere in this phase — every test in `tests/test_geometry_*.py` runs against `src/geometry/synthetic.py`'s generators or a hand-constructed toy array, per the pilot-first rule.

## Design

**Package layout** (`src/geometry/`), one module per spec subsection rather than one monolithic file:

- `trajectory.py` — straightness (§8.1), path length (§8.2), velocity (§8.3), curvature (§8.4), smoothness/acceleration (§8.5). Operates on one trace's `(T, D)` latent array at a time.
- `diagnostics.py` — the §9 collapse/triviality guards (embedding variance, covariance spectrum, effective rank, participation ratio as the intrinsic-dimensionality estimator, pairwise-distance distribution, terminal-state separability via silhouette score) **plus** a from-scratch trustworthiness/continuity implementation operating on two arbitrary precomputed `(N, N)` distance matrices — deliberately not `sklearn.manifold.trustworthiness`'s coordinate-only API, since §8.8 needs this between two independently-defined *distances* (latent vs. future-suffix), never two literal coordinate embeddings of the same space.
- `terminal.py` — progress toward terminal regions (§8.6): Euclidean centroids **and** a k-NN neighborhood-based alternative, per the spec's explicit instruction not to assume Euclidean prototypes are always valid.
- `branching.py` — branch separation over normalized prefix progress (§8.7): a Fisher-style between/within scatter ratio, binned over `s = t/(case_length-1) ∈ [0,1]` so cases of different lengths align.
- `future_equivalence.py` — future-equivalence neighborhood quality (§8.8): one `d_F` builder per candidate distance (edit/DL, activity-set Jaccard, n-gram Jaccard, remaining-time, outcome), rank correlation, precision@k, and the two decisive history-controlled tests, reusing `diagnostics.trustworthiness`/`continuity` rather than re-implementing them.
- `synthetic.py` — the §22 generator suite (straight line, circular arc, backtracking, collapsed, branching, reconverging).
- `_neighbors.py` — private shared k-NN/rank-matrix primitives used by both `diagnostics.py` and `future_equivalence.py`, so the "who are point i's k nearest neighbors" logic exists exactly once.

**New dependency:** `scipy>=1.11` added to `pyproject.toml` (Spearman rank correlation, `pdist`) — already an indirect dependency of `scikit-learn`, but declared explicitly since this package imports it directly rather than relying on an undeclared transitive install.

## Decisions worth recording

**Degenerate geometry returns NaN, never a silently-wrong number.** A collapsed trace (`z_1=...=z_T`) makes `straightness` compute `0/0` — returns `NaN`, not `1.0` (spec §9's own warning: "straightness can be artificially high if `z_1≈...≈z_T`" — treating collapse as `NaN` rather than a high score keeps this failure mode visible in any `nanmean` aggregation instead of biasing it upward). Likewise `curvature` returns `NaN` at any point where either adjacent displacement has near-zero norm: a stationary point's direction is undefined, and that must not be silently read as "zero turn" (which would be the opposite of the truth — a point sitting still on a collapsed trajectory should never register as maximally smooth).

**Intrinsic dimensionality: participation ratio, not a nonlinear estimator.** `diagnostics.participation_ratio` implements `(Σλ)² / Σλ²` over the covariance spectrum — a standard, simple, closed-form linear estimator. Explicitly *not* a manifold-nonlinear method (e.g. TwoNN, MLE-based estimators) — a deliberate scope decision for a first-pass diagnostic; revisit only if a later phase's real data shows this estimator is inadequate, not preemptively.

**Trustworthiness/continuity implemented from scratch on precomputed distance matrices.** `sklearn.manifold.trustworthiness(X, X_embedded, ...)` takes two coordinate spaces and applies one metric to compute both internally. Spec §8.8 needs to compare `d_Z` (latent Euclidean distance) against `d_F` (e.g. Damerau-Levenshtein distance over observable suffixes) — two spaces that are never both literal coordinates of the same kind. Implemented the standard Venna & Kaski (2001) formula directly against two arbitrary `(N, N)` distance matrices instead, hand-verified against a 4-point worked example (see Validation below) rather than trusted from memory.

**Branch separation uses a Fisher-style scatter ratio, not silhouette.** `branching.group_separation` = between-group scatter / pooled within-group scatter, generalized to ≥2 groups. Chosen over reusing `diagnostics.terminal_state_separability`'s silhouette score because silhouette is bounded to `[-1, 1]` and saturates, which would make it harder to see a *continuous* separation-over-progress curve rise and fall (§8.7's actual object of interest) — the unbounded scatter ratio has more usable dynamic range for that purpose. Returns `NaN` (not `0` or `inf`) when within-group scatter is exactly 0 (degenerate groups) — a real edge case the synthetic single-trace-per-branch case would hit, which is why `synthetic.branching`/`synthetic.reconverging` generate **multiple jittered traces per branch**, not one trajectory per side, giving `group_separation` non-degenerate within-group scatter to compute against.

**A bifurcation/predictive-horizon time is explicitly *not* computed in this phase.** `branching.branch_separation_curve` returns the raw per-bin separation statistic and omits any bin where fewer than 2 groups have data (rather than zero-filling it) — spec §8.7 requires defining an empirical bifurcation time "only if supported by robust statistical analysis," which is a Phase 6/8 question requiring real multi-case data and a proper significance test, not something to manufacture from a synthetic two-branch toy example.

**Synthetic trajectories carry independently-derived expected values, not hardcoded numbers.** E.g. the circular-arc test derives the expected chord length, path length, and constant per-vertex turning angle (`= total_angle / (n_points - 1)`, an exact property of equal-angle-spaced points on a circle) from closed-form geometry in the test itself, then asserts the implementation matches — so a test passing means the *formula* is right, not that a magic number was copied from the implementation's own output.

## Validation

44 new tests across 5 files (`tests/test_geometry_{trajectory,diagnostics,terminal,branching,future_equivalence}.py`), all synthetic/hand-constructed, all green:

- **`trajectory.py`**: straight line → straightness exactly 1.0, curvature/smoothness exactly 0 everywhere; circular arc → straightness and constant curvature matched against independently-derived closed-form values; backtracking → exactly one `π` curvature at the reversal, `0` everywhere else, straightness matched to an exact hand-computed fraction; collapsed → path length 0, straightness `NaN` (not 1), curvature `NaN` (not 0) at every point; length-1/length-2 traces return empty arrays/`NaN` rather than raising.
- **`diagnostics.py`**: collapsed data → effective rank and participation ratio both 0; isotropic Gaussian data → both ≈ D; exactly rank-1 data (all points on one line) → effective rank exactly 1; well-separated vs. interleaved clusters → silhouette high vs. near-0, `NaN` when underdetermined (<2 classes or a singleton class); **trustworthiness/continuity hand-verified against a 4-point worked example** (a swap of the two extreme points on a line) computed independently by hand against the Venna & Kaski formula — both equal `0.25`, matching the implementation exactly; identical spaces → both equal `1.0`; too few points for the requested `k` → `NaN`.
- **`terminal.py`**: centroids match hand-computed means; a trace walking straight to its own terminal point → strictly decreasing distance, `progress_trend = -1.0` exactly; constant distance → `NaN` trend (not a meaningless 0); k-NN class-distance alternative demonstrated to survive a multimodal terminal region where the Euclidean centroid lands ~40 units from either real cluster while the k-NN alternative correctly reports <2.
- **`branching.py`**: `group_separation` is `NaN` for <2 groups or degenerate (zero-scatter) groups, increases with between-group distance; the synthetic branching suite shows near-zero separation over the shared prefix, rising after the split; the synthetic reconverging suite shows separation rising then falling back down by the shared merge point, and `branch_separation_curve` reproduces that same rise-then-fall shape over binned progress.
- **`future_equivalence.py`**: every `d_F` builder checked against hand-worked sequences (identical/maximally-dissimilar edit distance; order-insensitive vs. order-sensitive activity-set/n-gram distance; time distance normalized by the observed max; outcome distance treating `None` as distant from everything, including other `None`s); `rank_correlation` exactly `±1.0` on constructed monotonic/anti-monotonic matrices; `precision_at_k` exactly `1.0` when the two spaces agree; **both history-controlled decisive tests validated against one fully hand-constructed 4-prefix scenario** (two similar-history pairs, four dissimilar-history pairs, `d_latent`/`d_future` built so each subset's correlation is exactly `+1.0` by construction) — confirms `dissimilar_history_retrieval` and `similar_history_divergence` correctly restrict to their respective mask before computing rank correlation.

`uv run pytest -q`: 80 passed, 1 skipped (pre-existing scaffold test, unrelated to this phase).

## A real bug caught while writing the tests

`future_equivalence.outcome_distance`'s first draft used `0.0 if outcomes[i] == outcomes[j] else 1.0` directly — but Python's `None == None` is `True`, so two prefixes with a missing outcome would have scored as identical (distance 0), contradicting the intended "missing is not a shared class" semantics documented in the same docstring. Fixed before any test was written against it (caught while drafting `test_outcome_distance_categorical_and_null_handling`, not by a failing test) by special-casing `None` to always return distance 1, including `None` vs. `None`.
